# 32a Visual Compiler 빠른 시작

## 실행

Windows에 Python 3가 설치되어 있고 Tkinter가 포함되어 있다면 다음과 같이 실행한다.

```bat
py 32a-visual.py
```

추가 패키지나 SDL2는 필요하지 않다. 어셈블러와 바이너리 컴파일 기능이 이 GUI 프로그램 안에 포함되어 있으므로 별도의 `32aasm.py`나 `16gasm.py`를 만들거나 설치할 필요가 없다. ChatGPT 등에서 미리 작성한 어셈블리 코드를 오른쪽 편집기에 그대로 붙여 넣고 즉시 컴파일할 수 있다.

## 화면 구성

- 왼쪽 위: 명령어 블럭을 순서대로 표시하는 블럭 플로우
- 왼쪽 아래: 블럭 개수, 예상 바이너리 크기, 선택 블럭의 상세 정보
- 오른쪽: 직접 편집할 수 있는 어셈블리 소스 코드
- 상단: 16g/32a 출력 형식, 컴파일, 코드 내보내기

GPU OP 블럭은 파란 계열, CPU OP 블럭은 초록 계열로 표시한다. 각 연결 화살표(JUMP, CALL, IF 건너뛰기, SHFL 입력)는 서로 구분하기 쉽도록 무작위 고대비 색상을 부여한다. 각 화살표는 무작위로 생성한 고대비 색상을 사용한다. 같은 연결을 다시 그릴 때는 색상을 유지하며, 새 연결에는 기존 화살표와 색조가 충분히 다른 색상을 배정한다.

## 블럭 추가 및 편집

1. 왼쪽 위 OP 목록에서 명령어를 선택한다.
2. `＋ 블럭`을 눌러 선택 블럭 뒤에 추가한다. 선택된 블럭이 없으면 끝에 추가한다.
3. 오른쪽 소스 코드를 직접 고쳐도 블럭 화면이 자동 갱신된다.
4. 블럭을 선택하면 왼쪽 아래에 OP 설명과 입력값이 표시된다.
5. 삭제 및 위/아래 버튼으로 명령어 순서를 바꿀 수 있다.

## JUMP/CALL 화살표

`JUMP` 또는 `CALL` 블럭 왼쪽의 작은 연결 지점에서 마우스를 눌러 원하는 목적지 블럭으로 드래그한다. 놓으면 해당 명령의 INPUT1/INPUT2가 상대 이동량으로 자동 변경된다.

어셈블리 코드에서 절대 목적지를 라벨 또는 블럭 번호로 직접 지정할 수도 있다.

```asm
start:
ADD 10, 20
JUMP ->start

CALL @subroutine
HALT
subroutine:
RET
```

`JUMP ->start`의 `start`는 라벨이며, `JUMP ->3`은 0부터 시작하는 블럭 번호 3으로 이동한다. `CALL`도 같은 표기를 사용한다. 라벨 없는 일반 형식 `JUMP 0, 3`은 런타임의 상대 입력을 그대로 지정한다.

## SHFL 예상 화살표

`SHFL A, B`는 다음 비-SHFL 명령의 두 입력을 결과 이력에서 가져오도록 지정한다.

- `0`: 원래 입력값을 사용하므로 화살표가 없다.
- `1`: 가장 최근의 결과를 만든 블럭
- `2`: 두 번째로 최근의 결과를 만든 블럭
- 그 이상: 해당 순번의 과거 결과 블럭

각 SHFL 입력 화살표는 서로 다른 무작위 색상으로 표시된다. 화살표의 색상만으로 A/B를 구분하지 않고, 화살표 옆의 `SHFL A` 또는 `SHFL B` 라벨로 입력 종류를 확인한다. 이 연결은 소스의 직선 실행 순서를 기준으로 계산한다. IF/JUMP/CALL/RET 등 제어 흐름이 있으면 실제 실행 이력은 달라질 수 있어 점선과 `?`로 불확실성을 표시한다. 해당 시점에 충분한 결과가 없으면 경고가 표시된다.

## 컴파일

상단 출력 형식에서 `32a` 또는 `16g`를 고르고 `컴파일`을 누른다.

- `.32a`: GPU OP 16개와 CPU OP 16개, 총 32개 OP
- `.16g`: GPU OP 16개만 지원. CPU OP가 포함되면 컴파일 오류

바이너리는 OP 1바이트 + INPUT1 2바이트(big-endian) + INPUT2 2바이트(big-endian) 레코드로 저장하고, 레코드 사이에 `0x26` 구분자를 넣는다. 이 프로그램은 실제 32a/16g 런타임과 같은 고정 5바이트 레코드 방식으로 저장 결과를 다시 검사한다.

예상 파일 크기는 `명령어 수 × 5 + (명령어 수 - 1)` 바이트다.

## 지원 숫자 형식

```asm
ADD 123, 456
ADD 0x0010, 0x0020
ADD 0b1000, 0o10
```

모든 입력은 unsigned 16비트(0~65535)다. 한 개의 입력만 사용하는 명령어는 두 번째 입력을 생략할 수 있으며 0으로 채운다. 입력이 필요 없는 `HALT`, `RET`은 피연산자를 생략할 수 있다.


## 컴파일러 내장 구조

이 프로그램은 소스 파싱, 라벨 해석, JUMP/CALL 상대 이동 계산, OP 검증, 바이너리 인코딩 및 출력 파일 검증을 자체 수행한다. 별도의 `32aasm.py`를 호출하거나 요구하지 않는다. `32aasm.py`는 이 프로젝트의 필수 파일이 아니며, Visual Compiler 자체가 프롬프트에서 준비한 코드를 바로 컴파일하는 독립 프로그램이다. `.16g` 출력은 GPU OP 16개만 허용하고, `.32a` 출력은 전체 32개 OP를 허용한다.
